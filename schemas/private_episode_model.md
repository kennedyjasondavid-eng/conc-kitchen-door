Adding episodeId to JSON alone would lose it on several paths or allow an edit/instruction to land on a different occupant after an await. Preserve these current workflows until a reviewed private lifecycle adapter can replace every relevant seam together.

## Proposed API and types

`config={schema:1,privateRepositoryId}`: fixed positive safe integer; no public destination or caller-supplied URL.

`source={schema:1,privateRepositoryId,lease:{sourceId,revision,digest},snapshot:{schema:1,residents,anaphRooms,queue,reservedEpisodeIds,...}}`. sourceId is a nonsemantic UUIDv4 for the approved operational source/lease, revision a nonempty opaque source revision, digest sha256 over the ENTIRE canonical snapshot (sorted object keys, array order preserved, no field stripping). Snapshot must be explicit finite JSON; all four listed arrays required, even when empty. All clinical/source fields stay opaque and covered by the digest, not parsed into diagnoses. Source owner selection, authentication, freshness and competing-device reconciliation are future trusted transport/admin responsibilities; a timestamp, matching count, a field saying verified or this pure function cannot establish those facts. Do not assume repo door_state is current over newer live device/private authority.

Initial planner requires queue empty and no existing top-level episodeId/residentEpisodeId/occupancyId/residentId/id on current rows: nonempty queue, partial IDs or unknown lineage require review, never auto-apply/dedupe/guess. This holds only the assignment plan, not ordinary intake/edit/private draft save. Each row must have a nonempty unique normalized occupancy locator(room) to reject ambiguous legacy duplicates; the locator is not a persistent person ID. An empty verified roster is distinct from missing/unavailable source. reservedEpisodeIds is an explicit private source/history list, never omitted-as-empty; supplied new UUIDs cannot reuse it. Proving that list is complete remains a future authenticated lifecycle-source prerequisite.

Room normalization is EXACT trim+ECMAScript lowercase only; do not strip leading zeroes, punctuation, bed suffixes or merge distinct locators. Finite JSON/Unicode validation occurs BEFORE JSON.stringify cloning or hashing: reject undefined/function/symbol/BigInt, nonfinite numbers, sparse arrays, cycles, Date/nonplain instances, accessors and toJSON hooks without invoking them. Reject lone UTF-16 surrogates in keys/values (valid pairs allowed), avoiding TextEncoder replacement collisions. Preserve all ordinary JSON fields and array order; no silent omission/null conversion. Repeated ordinary data references may be copied by value (legacy preferences/accommodations share arrays); distinguish those from cycles. Cross-realm ordinary JSON fixtures must remain valid. Dangerous direct patch keys __proto__/constructor/prototype reject, never mutate prototypes.

`candidate={schema:1,operationId,expectedLease:{sourceId,revision,digest},assignments:[{sourceRow,episodeId}]}`. sourceRow is an integer ordinal in this exact leased array, never a persistent identity or runtime room predicate. Assignments must be a bijection over ALL source rows, with distinct externally supplied UUIDv4 episodeIds, no reserved ID reuse. No UUID generation inside either API; repeated same candidate/source is deterministic. A room reorder, same-count replacement, note/tag change, pending queue change or any source field change invalidates the lease. Do not copy row selectors to another lease.

`await doorPrivateEpisodeV1Plan(source,candidate,config)` returns `{ok:true,plan}` or `{ok:false,code}`. Plan strict allowlist: `{schema:1,privateRepositoryId,operationId,source:{sourceId,revision,digest},assignments:[{sourceRow,episodeId}],planDigest}`. planDigest is sha256 of this semantic plan WITHOUT planDigest; no selfhash. Output has no resident records, clinical directions, raw source evidence, credentials, public projection or effect. New IDs and row selectors are private metadata.

`await doorPrivateEpisodeV1Check(plan,currentSource,config)` revalidates the complete plan/digest and independently reread current source/config. Returns `{ok:true,status:'current-plan'}` or rejection. Require exact repository and source lease identity/revision/digest plus fresh recomputation over all snapshot bytes/fields; no clock ordering, room lookup, remapping, forced rebase or repair. Every async API snapshots ALL inputs before first await and never mutates them. Unknown extra input fields never spread into returned plan/result, but source snapshot extras remain part of its digest.

## Private state and initialization

`await doorPrivateEpisodeV1Initialize(plan,currentSource,config)` runs the complete plan/current-source checks over ONE detached input frame, then returns `{ok:true,state}`. This is a PRIVATE working-state candidate, not an accepted registry or write effect. Strict state shape:

`{schema:1,privateRepositoryId,epochId,revision,source,records,closed,history,reservedEpisodeIds,operations,sidecars,requiresServingRevalidation:true}`.

epochId=plan.operationId, revision=1, source=plan.source. Active records are `{episodeId,revision:1,resident:<detached entire original row>}` in source order. Closed/history/operations start empty. Preserve source resident._history privately as OPAQUE UNVERIFIED LEGACY evidence; do not promote it to episode-owned kernel history or restore from it. Reserved IDs are the union of source reserved history and all assigned IDs. sidecars contains the original detached anaphRooms; it is not reclassified or cleared. No former-person data is invented. Initialization is deterministic with fixed supplied mapping; future private transport must reject a second initialization over an already accepted identity epoch, and bind the immutable operation/plan digest. This pure API cannot authenticate an outbox or freshness journal.

state.source records INITIAL ancestry only, not freshness after subsequent operations. Later currentness requires authenticated private source/epoch/revision plus actual repository CAS; the initial lease alone cannot authorize a later edit. All four APIs apply the same raw finiteJSON/well-formed-Unicode validation BEFORE any clone/hash. Room normalization remains exact trim+lowercase.

State invariants: fixed configured private repo and UUID epoch; safe positive integer state/record revisions; unique active episode IDs and normalized rooms; unique closed episode IDs disjoint from active; every active/closed ID reserved; finite JSON resident payloads; unique operationId journal entries with intent digests; unique history(episodeId,recordRevision); persistent requiresServingRevalidation MUST be true in this version. Missing/false marker is invalid, never defaulted to clinical readiness. ID aliases and wrapper identity/revision are protected, not clinical payload fields. Closed episodes and history never become active through a room lookup.

## One pure reducer and retry rules

`await doorPrivateEpisodeV1Reduce(state,event,config)` snapshots ALL arguments before first digest await. Event common fields: `{schema:1,operationId,expectedEpochId,expectedStateRevision,type,...typed intent}`. Fixed repo/epoch, explicit target identity and revisions are mandatory. No clock, random UUID, network or storage access. Output is `{ok:true,state,replayed,requiresServingRevalidation}` or `{ok:false,code}`; never a write effect or public data.

Unknown typed event/action/move/patch-control keys reject rather than being silently omitted from the intent digest. Resident payload values remain opaque finite JSON, with protected locator/identity/history fields governed below; do not add a clinical parser. State/plan/result container outputs are strict owned allowlists. Dangerous direct patch keys __proto__/constructor/prototype reject without getter invocation or prototype mutation.

Compute intentDigest over configured repo, epoch, operationId and the COMPLETE normalized typed intent including target episode revisions/payload, EXCLUDING only expectedStateRevision (a context lease, not new intent). Before a new operation, expectedStateRevision must equal current state.revision. If a journal entry already holds operationId with the same intentDigest, return detached CURRENT state with replayed:true and no reapplication, even if a newer legitimate edit advanced revisions. Different intent under that ID rejects. After a successful new operation increment state.revision ONCE, record the journal entry and set requiresServingRevalidation:true. No partial result on rejection.

A refresh may update the context state lease for an unapplied operation only after reading current authoritative private state; target episodeId/expected episode revision and intent stay fixed. If another occupant now uses the same room, the old episode is missing/closed and the edit rejects. No fallback by room/name/clinical similarity. Equal serialized fields do not establish occupant continuity. Repository CAS/authentic current-source selection remain separate future transport requirements.

Persistent pending marker is set at Initialize and every successful new operation and preserved across JSON roundtrip/replay. No event clears it. Successful/replayed output mirrors that pending state; replay cannot claim ready because this operation made no additional edit. A future serving owner must bind an explicit verification/admission proof to EXACT private source/epoch/revision and reconciled sidecars before service admission; this kernel supplies no such proof and cannot clear/remap anaphylactic containment. An old return-only flag is insufficient after persistence/restart. No current-ready claim can be derived from this working state alone.

## Supported explicit lifecycle intents

| Type | Intent and exact behavior |
|---|---|
| edit | episodeId, expectedEpisodeRevision, patch:{set,remove}. Apply explicit field changes to existing resident payload; absent patch fields stay unchanged, set:null remains explicit null, remove is an explicit deletion. Reject set/remove overlap/duplicates and protected room, ID aliases or legacy _history edits. Increment that record revision and append prior record snapshot to kernel history. No diagnosis/tag/clinical inference. |
| move | moves:[{episodeId,expectedEpisodeRevision,toRoom}]. Simultaneous explicit move set permits swaps; final normalized rooms must be unique including nonmoving records. Preserve episode/payload except room, increment moved record revisions and retain prior snapshots. No IDs minted or records merged. |
| intake | newEpisodeId supplied UUIDv4, resident fresh explicit payload with vacant room. Reject occupied destination, any ID ever reserved/active/closed, and ANY presence of episodeId/residentEpisodeId/occupancyId/residentId/id/_history in the supplied payload (even empty/null); never strip and reuse them. New record revision1; no automatic prior payload/history/instruction carryover. A deliberate occupied-bed replacement is atomic queue(discharge exact old episode, intake new ID), never implicit overwrite. |
| discharge | episodeId+expectedEpisodeRevision. Remove active row and append a closed tombstone containing that episode, final record revision, closing operation and detached prior payload. Keep ID reserved and preserve closed source/history privately. Do not clear anaph sidecars or transfer instructions to the next occupant. |
| restore-active | episodeId+expectedEpisodeRevision+targetHistoryRevision+fields. Only an ACTIVE SAME episode and its actual stored history may supply explicitly selected payload fields. Protect current room/identity/revision, legacy _history and current serviceInstructions (including removal tombstones); those cannot be restored through this convenience action. Requested fields must exist in the selected history; use explicit edit for a new reviewed change. Increment revision and keep an audit snapshot. Closed/missing episode, wrong historical owner and ambiguous continuity reject/review; re-intake needs a fresh ID. |
| queue / import | actions:[supported non-batch typed intents]. Apply atomically to a detached working copy in declared order, record one outer operation journal entry and increment global revision once. Target record revisions are checked at each projected step. Missing import rows NEVER imply discharge; imported known persons require exact episode/revision, new intakes explicit new IDs, moves explicit. Unidentified/fuzzy room/name matching, nested batches or unsupported action rejects the WHOLE operation; raw import/queue input can remain an external private draft for review. |

Resident clinical values/instructions stay opaque and episode-owned. A set/remove or explicit selected restore is a recorded staff intent, not a clinical approval; current source evidence and normal review still apply. Anaphylactic flags and room-list containment are not an identity-derived diagnosis. Preserve anaphRooms byte-for-byte in this kernel, preserve explicit payload flags except a targeted edit, and require existing containment/routing/plating revalidation on changed working input before any service release. Do not fork those owners into this reducer or treat its success as acknowledgement/clinical readiness. Sidecar reconciliation is part of future active orchestration, not silently skipped here.
