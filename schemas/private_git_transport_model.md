## Strict configuration and injected capabilities

Config exact keys: `{schema:1,privateRepository:{id,owner,name,branch},publicRepositoryId}`. IDs distinct positive safe integers; owner/name match bounded GitHub identifier characters, no slash/URL/query/dotdot/whitespace; branch is a bounded unqualified branch name, not a SHA, refs prefix or payload-supplied ref. For this first adapter support only simple branch names `[A-Za-z0-9][A-Za-z0-9._-]{0,99}` excluding dotdot, trailing dot, @ and .lock. Branch omission is invalid. These restrictions do not change GitHub's general branch semantics; additional branch forms need explicit later support. Unknown config keys reject, including public/private destination URLs or arbitrary paths. All URLs constructed under https://api.github.com, using fixed trusted owner/name/branch; no payload URL is fetched.

Capabilities exact callable members: `request`, `getCredential`, `deriveProjectionBasis`. No fallback to fetch, DEFAULT_SETTINGS, PublishAuth, localStorage, legacy keys or default token. getCredential receives only `{repositoryId:fixedPrivateId,permission:'contents-write'}` and returns a nonempty single-line token string (max2000 characters); missing/denied token rejects before requests. Credential is passed only as Authorization header to fixed api.github.com endpoints, never URL/query/body/commit text/results/errors. Authenticated private reads also use this administrative capability; future read-only viewers are outside this bootstrap transport.

request receives adapter-created `{url,method,headers,body,timeoutMs,maxResponseBytes,redirect:'error'}`. Method GET or fixed GraphQL POST only. It returns `{status,url,redirected,bytes:Uint8Array}`; response URL must exactly equal requested URL and redirected must be false. HTTP status/error payload never establishes path absence. Trusted request implementation must enforce deadline/abort and byte cap while streaming before buffering; the adapter independently rechecks byte count and fatal UTF8 decoding. No automatic retries, hidden redirects, caching or network fallback. Injected request is the trusted authenticated-HTTPS boundary; implementing its actual fetch bridge later is a separate review, not a claim this mockable adapter authenticates arbitrary objects.

Fixed bounds in this revision: request timeout15000ms; authority JSON16KiB; manifest64KiB; each registry/menu file4MiB; tree JSON2MiB and10000 entries; blob REST JSON wire6MiB (base64 overhead included); metadata/commit/GraphQL JSON1MiB; at most96 requests and24MiB raw response-wire bytes per method. Reject before reading further on exceeded limits; bound generation paths to known depth. Tests use tiny values beneath these production caps and explicit over-cap canaries. Abort after a mutation POST may have started is unconfirmed, not proof no write occurred.

deriveProjectionBasis receives a detached allowlist `{generationId,operationId,files:{'registry.json':UTF8String,'menu.json':UTF8String}}`, WITHOUT manifest/basis/witness fields. It returns a supported sha256 hash or fails closed. It is the trusted independent canonical-input owner capability; this slice provides no production basis algorithm and must not invent one or copy a manifest digest. Tests use a deterministic independent synthetic function. Exact derived result must equal the reviewed operation/manifest expected basis. Captured raw private file strings remain private in memory; no new evidence fields/occupant schema are implied.

## Immutable reads and private partial frame

Revalidate REST repository metadata ID, full_name, private:true and permissions.push:true on every method, before any private content request. Renamed/transferred/wrong/public/view-only repositories fail, not redirect/reconfigure. Then read the exact fixed Git branch ref and its commit. Validate full refs/heads/<configuredbranch>, commit object SHA and immutable root tree SHA. Git tree/blob response SHA must equal the requested object SHA. Nonrecursive tree requests OMIT recursive entirely (even recursive=false requests recursion in GitHub). Reject truncated/malformed/duplicate tree entries, non-040000 directory nodes and non-100644 file blobs, symlinks/submodules, path traversal, escaped separators, ambiguous names, size/encoding mismatch and invalid JSON. Build subsequent API URLs from fixed repo plus validated object SHAs, never response URL fields.

Absence of accepted.json is legal ONLY when the authenticated exact root tree has no such entry. HTTP404/403/timeouts/missing intermediate subtree are unavailable or malformed, not accepted-path absence. Generation directory/file absence is a distinct package error. Return no absent status from parse failures.

`observePrivate()` reads current accepted.json at captured HEAD. If absent return `{ok:true,frame:{schema:1,repository,head,accepted:authenticatedAbsentRead}}`. If present, validate exact schema1/gen/op/explicit-nullable-parent pointer; read generations/<pointergeneration>/{manifest.json,registry.json,menu.json} at THAT SAME immutable HEAD; validate actual accepted.json pointer, manifest parent/schema/identity, file SHA256 and independently derived basis through existing validators. Return `{ok:true,frame:{schema:1,repository,head,accepted:authenticatedPresentRead,package,expectedProjectionBasisDigest}}`. Frame is private, detached and not a complete public/bootstrap/clinical current-ready receipt. Later head movement does not rewrite the captured frame or imply it remains latest.

`readPackage(reference)` requires exact full foundation reference with supported immutable40hex privateCommit, never a branch. Verify fixed accepted.json at that exact commit and require it matches reference generation/op and manifest nullable parent. Read the fixed generation directory at that same commit; require all three entries and no unapproved generation child files, derive independent basis, validate package. Return `{ok:true,package,expectedProjectionBasisDigest}`. Never substitute current main/accepted HEAD if the requested commit is missing or superseded. Reading an unreachable commit package alone does not establish that the operation became branch acceptance; no accepted/shared success state is returned by this method.

## Immutable create and private acceptance

acceptPrivate accepts a reviewed bootstrap operation only in prepared/private-unconfirmed phase, with no privateCommit or release flags, correct fixed repository IDs and valid captured heads/nullable parents. manifestText must parse as the reviewed manifest allowlist, bound exactly to operation gen/op/parent/witness/independent basis; files exact keys registry.json/menu.json with UTF8 strings and supported SHA descriptors. Reject extra/missing paths or duplicate manifest descriptors. Validate all file SHA256 and deriveProjectionBasis BEFORE mutation, without inventing a placeholder future commit to satisfy the initialized validator. Construct accepted.json exclusively from operation gen/op/explicit nullable parent, never a supplied pointer. No target privateCommit appears in precommit files.

Reobserve authenticated current private authority and require exact expectedPrivateHead AND full nullable parentAccepted match. Do not inspect current public HEAD to permit/reject this private transaction. Prove generations/<newgenerationId> is ABSENT in that captured parent tree; an existing directory/file of any kind rejects generation-exists even if bytes look identical. Never use FileAddition to overwrite an existing generation. An already-landed operation is handled through new observation/controller recovery, not by bypassing immutability or resetting pointer with another write. Preserve all existing unrelated private files; no deletions, source branch creation, force push or alternative REST write fallback.

Send exactly one fixed GraphQL createCommitOnBranch mutation. Use fixed repositoryNameWithOwner and branchName; expectedHeadOid is exact operation.expectedPrivateHead. fileChanges contains additions ONLY for generations/<id>/manifest.json, registry.json, menu.json and root accepted.json. UTF8 bytes encoded strict padded RFC4648 base64. Commit headline fixed 'Accept private DOOR generation'; clientMutationId is opaque operationId. No resident name, room, diagnosis, product evidence or caller-provided commit message in metadata. Payload cannot choose arbitrary query/document, branch, owner, deletion, headers or message.

Official GitHub commits reference confirms mutation appends a commit and updates its branch, with expectedHeadOid naming the expected prior head: https://docs.github.com/en/graphql/reference/commits#createcommitonbranchinput . FileChange encoding: https://docs.github.com/en/graphql/reference/git . REST trees: https://docs.github.com/en/rest/git/trees . REST force:false alone is not exact-head CAS and is prohibited as substitute.

## Acknowledgement, timeout and races

HTTP200 alone is not success. Any GraphQL errors, missing/mismatched commit/ref/parent/repository data, timeout/abort or unreadable readback after POST could have started returns `{ok:false,code:'private-unconfirmed',operation:capturedOperation}`. Never echo GraphQL error messages/paths/body. Before POST, malformed input returns invalid-input, unverifiable authority unavailable, wrong repository repository-mismatch, stale captured parent conflict and existing generation generation-exists. No automatic retry. Rate-limit/permission/branch-protection failures never trigger weaker mutation routes.

On apparent mutation success, require actual returned commit/ref belong to fixed repository/branch, returned ref target equals commit, actual single parent equals captured HEAD and returned commit differs. Authenticated GET commit/tree/blob readback at returned immutable SHA must reproduce EXACT snapshotted manifestText, registry/menu bytes and constructed accepted pointer, with full package validation against the independent operation basis. Revalidate repository confidentiality/identity before success. Return `{ok:true,kind:'private-accepted-at-commit',event:{type:'private-accepted',operationId,receipt,package},operation}`. Receipt is the existing authenticated-git-cas-commit form derived only from this matched native mutation acknowledgement and immutable readback, not caller-supplied CAS flags.

A later branch commit may land before readback. Successful exact operation commit acknowledgement remains durable history; this result does NOT claim it is current latest accepted/private input. A new observePrivate obtains later authority, which the controller must preserve. Do not replace receipt.commit.sha with later branch HEAD or assert that later descendant has original direct parent. If response was lost and later observation finds matching generation/op at a descendant, return the read frame only: the future controller composes public context and calls BootstrapRecover. Do not fabricate a private-accepted CAS event from a read-only descendant observation. Unreachable commit objects and caller-retained JSON are not substitutes for accepted branch authority.

GraphQL expectedHeadOid closes the branch-head race after preflight: concurrent writers/code commits cannot both win from the same parent. No atomicity exists across private/public repositories or repository visibility administration. Fixed trusted administrator configuration must forbid visibility/ownership changes during operational connection use; pre/post checks detect observed drift but cannot provide an atomic GitHub visibility+commit transaction. A discovered visibility change after a possible write is an incident/unconfirmed result, never permission to copy/delete/rewrite history automatically. Actual operational setup/permissions review remains before any live use.

### Pre-builder API/wire correction and freeze amendment (revision1b)

GraphQL Ref response is name:'main' plus prefix:'refs/heads/' for this fixed branch; request both and require exact name/configured branch and prefix refs/heads/, plus repository/target. The fixture correction updates synthetic protocol shape, not safety expectations. Some commits-reference narrative uses older field wording; current input-field table controls.
