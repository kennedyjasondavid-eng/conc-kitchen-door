No source, storage, network, credential, hydration, migration, resident-ID assignment or cutover implementation. Existing initialized foundation46 gates remain unchanged.

The approved private repository is README-only. Its real identity/head is an eventual trusted transport observation, never a fixture UUID/commit. All gate identities below are synthetic. The API does not authenticate an arbitrary JavaScript object: future authenticated fixed-repository transport must supply these observations/receipts. ## Shared types

`config={schema:1,privateRepositoryId,publicRepositoryId}`. Repository IDs are distinct positive safe integers pinned by approved administrator setup. Configuration has no global projection-basis digest: newer accepted and older serving frames may legitimately have different bases. Do not derive a target repository from a publication pin or payload. Actual configured IDs/credentials are not created in this slice.

`repository={id,visibility,permissions:{push:true}}`. Private visibility must be private; public delivery repository visibility public. A wrong ID/visibility, missing write capability, error/403/network response, redirected source or unreadable Git state rejects bootstrap observation/planning. Write permission is required because this is an administrative initialization contract, not the future read-only viewer API.

An authority read is `{status:'absent'|'present',source:'authenticated-git-tree',path,atCommit,value?}`. For absent, value must be omitted. Absence means the fixed path was established absent in the authenticated Git tree at the exact captured40-hex head; an HTTP/Pages404 or catch-all network failure is not absence. Private path is accepted.json; public path is protocol-v1/publication.json. A status error/unknown, branch name, mismatched atCommit, missing authority read, malformed value or a supplied dummy predecessor rejects. Every read/package belongs to the pinned repository and exact commit, without latest-branch fallback.

`observation={schema:1,private:{repository,head,accepted,package?,expectedProjectionBasisDigest?},public:{repository,head,pin,package?,projection?,expectedProjectionBasisDigest?}}`. Heads are actual captured Git commits, including the README/public code heads when neither data path exists. Private accepted.value is `{schema:1,generationId,operationId,parentAcceptedGenerationId}`; its package is the existing foundation bundle at private.head. Public pin.value has the existing generation reference fields; its package is read from the fixed PRIVATE repository at pin.privateCommit, not private.head; projection is the existing allowlisted DTO snapshot bound to that pin. Each PRESENT frame requires its OWN independent expectedProjectionBasisDigest (supported sha256); accepted and serving digests may differ. The trusted future canonical-basis caller computes this expected value from that exact frame's inputs, never copies it back from the manifest or substitutes the other frame's value. This API compares the separately supplied expected value; it does not invent that future canonical hash implementation. No confidential raw package is returned in state.

For EVERY package (current accepted, pinned serving and private commit receipt), bundle.accepted specifically means the authenticated fixed accepted.json readback at bundle.commit in the fixed private repository, not a manifest-derived copy, cached/latest pointer or unverified candidate. It must have schema1 and all three pointer fields: generationId, operationId and an explicitly present parentAcceptedGenerationId (null or valid prior ID). Require its whole pointer identity/schema/nullable parent to match the manifest; Observe additionally matches it with private.accepted.value when reading current accepted authority; Apply private acceptance additionally matches it with the operation's captured nullable parent. The initialized foundation only checks gen/op: these bootstrap wrapper checks are additional and MUST NOT weaken/change its46 gates. A missing parent is not an implicit null; mismatched/unsupported/missing pointer schema rejects. Future transport must prove the actual fixed-path read at the exact commit; the pure API cannot authenticate an arbitrary supplied object.

`state={schema:1,phase,repositoryIds:{private,public},privateHead,publicHead,accepted,serving}`. repositoryIds are copied from the fixed config and must match it on every later API call. accepted and serving are full foundation references when present, otherwise null. Legal states only:

- uninitialized: accepted:null and serving:null, with both verified path absences and real heads.
- accepted-never-served: accepted reference present, serving:null, with verified private package and verified public pin absence.
- initialized: accepted and serving references present with independently verified packages and public projection. They may differ; initialized is an authority-shape fact, not a current/clinical suitability claim. The existing strict serving-eligibility primitive still decides exact accepted/pin equality.

Public serving present without accepted private authority is invalid/unavailable. Malformed/unavailable input never becomes uninitialized. State and operation results are detached strict allowlists containing references only. Unknown schema rejects. An initialized state cannot be reset to null or prepared for first creation through bootstrap. Plan/Apply require state.repositoryIds exactly equals configured IDs; Apply/Recover also require operation.repositoryIds exactly equals configured IDs. A persisted state/outbox operation cannot be silently retargeted when configuration changes; legitimate repository migration needs a separately reviewed protocol.

## API1 — observe

`await doorPrivateBootstrapV1Observe(observation,config)` returns `{ok:true,state}` or `{ok:false,code}`. Validate the fixed repositories, permission, exact authenticated Git authority reads and all schemas. Use doorPrivateV1ValidatePackage for each present package with its exact derived reference and `{repositoryId:config.privateRepositoryId,publicProjectionBasisDigest:thatFrame.expectedProjectionBasisDigest}`; additionally require accepted pointer/manifest parent identity to agree. Missing/mismatched expected basis rejects; never compare a manifest field to itself. For public serving use doorPrivateV1ProjectPublic and require its generationRef exactly equals the pin. Do not call the initialized Transition/Recover with null placeholders. Existing foundation references/helpers may be reused without loosening their46 frozen checks.

This pure observation validates the receipt supplied by the future transport, not the whole future public F4 carrier/seal or current physical preparation. Publication flow/paired-reader/device activation remain separate gates; no new producer claims are added here.

## API2 — prepare a private transaction

`doorPrivateBootstrapV1Plan(state,candidate,config)` returns `{ok:true,operation,effect:'write-private'}` or rejection. It accepts only uninitialized/accepted-never-served states. Candidate is `{schema:1,generationId,operationId,publicInputWitness,publicProjectionBasisDigest}` with new random nonsemantic IDs, supported hashes and no privateCommit/guessed future commit. The candidate's independently computed precommit basis is copied into its operation and is never reread from the resulting manifest as its own validation. IDs must not reuse current accepted generation/operation. No runtime ID generation occurs inside the pure API.

Operation is `{schema:1,repositoryIds:{private,public},generationId,operationId,publicInputWitness,publicProjectionBasisDigest,expectedPrivateHead,expectedPublicHead,parentAccepted,expectedServing,phase:'prepared'}`. Copy repositoryIds from verified state/config. Capture both heads and the actual nullable accepted/serving parents from state; no synthetic predecessor. The effect authorizes no network I/O in this slice. A future transport must atomically create the immutable generation and accepted pointer in one private Git commit, with the captured private head as its CAS parent. The manifest witness/basis excludes its not-yet-known privateCommit.

## API3 — apply observed transaction events

`await doorPrivateBootstrapV1Apply(state,operation,event,config)` returns `{ok:true,state,operation,effect?}` or rejection, without mutating any input. Operation is separate from state so a newer privately accepted edit can coexist with acknowledgement of an older public commit. All events bind operationId. Legal operation phases are prepared, private-unconfirmed, accepted-release-pending, public-prepared, released and released-stale. Unknown phase rejects. Returned operation allows only its listed plan fields plus actual privateCommit and the later latestInputReleased/needsRebase booleans. Candidate/state/op/event/config unknown fields are never spread into returned state/operation/effects; raw payload/evidence canaries must be absent. No arbitrary rollback/reset event exists.

A successful transport commit receipt is `{kind:'authenticated-git-cas-commit',repository,commit:{sha,parents:[expectedHead]},refUpdate:{before:expectedHead,after:sha,compareAndSwap:true}}`. Require one exact parent and expected ref lease, different actual commit, fixed repository/capability, supported commit formats. This is a returned and verified actual transport commit; never populate it from a candidate or selfhash. The future writer/readback must establish authenticity; this pure API cannot do so by itself.

- private-accepted: event includes receipt and full foundation package at receipt.commit.sha. Require current state.privateHead==operation.expectedPrivateHead and state.accepted==parentAccepted; validate exact manifest/accepted gen+op+nullable parent, operation.publicProjectionBasisDigest and atomic package at the returned commit. Then advance privateHead/accepted, retain publicHead/serving, attach actual privateCommit to operation and phase accepted-release-pending. A retry of the exact already accepted operation/commit is idempotent; a different/newer accepted head rejects rather than overwrites. A duplicate private acknowledgement after public release MUST preserve released/released-stale phase and serving/publicHead; it cannot downgrade the operation to release-pending. Meal incompleteness cannot block private acceptance.
- private-unconfirmed: allowed only from prepared/private-unconfirmed with no confirmed actual privateCommit, no authority advances; phase private-unconfirmed. A failed/timed-out request is not proof of absence and not a shared save. Recovery must reread authoritative Git state before choosing retry/acknowledgement. A late private timeout from accepted-release-pending/public-prepared/released/released-stale rejects without phase/state downgrade.
- public-prepare: require operation's actual accepted target remains latest accepted and privateHead current; expected public head and nullable expected pin still match. Validate event.projection with the existing public DTO projector and exact target generationRef. Return effect `{type:'write-public',expectedPublicHead,expectedServing,projection}` and phase public-prepared. Projection is the detached allowlisted DTO; no raw/private fields enter the effect. If newer private input arrived, return rejection/no public effect; registry input remains accepted and editable.
- public-unconfirmed: allowed only from public-prepared/accepted-release-pending with an actual validated privateCommit. Private accepted input remains durable, public authority unchanged; phase accepted-release-pending. A late public timeout from released/released-stale (or no accepted target) rejects without phase/state downgrade. No false service-ready claim. Same operation is retried only after recovery verifies both parents.
- public-committed: require a previously public-prepared operation (or exact already released duplicate), exact PUBLIC receipt/CAS lease plus authenticated fixed-path pin readback at the returned public commit, matching operation target; validate its pinned private package against operation.publicProjectionBasisDigest and validate projection. The serving pin becomes that observed target and publicHead becomes actual commit on first acknowledgement. Keep latest accepted/privateHead untouched. Return initialized state. If accepted advanced during the public write, set operation.phase released-stale/latestInputReleased:false/needsRebase:true; otherwise released/true/false. Do not add a private activation tail write. Exact duplicate acknowledgement is idempotent. If a later verified public HEAD retains the SAME pin, an old acknowledgement must keep that later state.publicHead, never replace it with the old receipt commit. A different/superseding current serving pin rejects, never rolls back. No lexical/timestamp ordering of opaque commits is used.

The nullable expectedServing comparison is exact: verified absence equals only null, not an arbitrary reference. A public code-head advance is not silently substituted into the captured write lease. A new approved retry/rebase requires a fresh authoritative observation proving the serving parent unchanged.

## API4 — restart/recovery

`await doorPrivateBootstrapV1Recover(operation,observation,config)` calls Observe internally; invalid/unavailable observations return rejection/review without a write effect. It returns `{ok:true,state,operation,action,latestInputReleased,needsRebase}` with no I/O.

- Exact public target landed and verified: ack-released; latest flag compares current accepted with target. No duplicate publish. Preserve any newer private accepted state.
- Released/released-stale operation but authoritative serving regressed to old nullable parent/absence: review/superseded, never resume-public or retry-private, regardless of plausible old heads. Confirmed release history is not erased by a later missing/readback pointer. A deliberate rollback/reset needs a new separately reviewed operation.
- Accepted target verified and public pin still the captured nullable parent at expected public head: resume-public, retaining actual private commit. A lost private receipt may recover the commit only from this verified matching generation+operation observation, not a candidate guess.
- Same accepted/pin but public head changed: review-public-head; do not overwrite/substitute a new lease silently.
- Neither accepted nor serving exists and both captured heads remain: retry-private with SAME random IDs/content; no phantom first serving frame. Prepared/unreachable Git object is not an accepted pointer. If operation already claims a different accepted commit but authoritative pointers are absent, review instead of blind overwrite.
- Another initializer/newer accepted or different serving authority: superseded/needsRebase:true. No replay over it. Changed private head despite accepted-path absence: reread-rebase, not blind first creation.
