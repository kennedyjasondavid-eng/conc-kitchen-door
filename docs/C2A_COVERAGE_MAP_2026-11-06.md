### Independent-review correction: current Corn floor

Independent food/data review demonstrated that current structural coherence alone did not reject a coherently lost Corn flag. The first draft's historical-only replacement was insufficient; the current operational flags were correct, and the reviewer injected the loss in memory. The historical assertions above remain, with two additional checks in `corn_recipe_alignment_gate.mjs`: an independent exact-binding oracle and a current-data Corn warning floor. The floor follows any attached recipe by explicit ID, or an exact unique recipe name when no ID exists. It requires the current regular/shared slot and meal flags for known source Corn, and reads the real vegan/halal plate warning for those alternate slots. Vegan-only Corn is not promoted to the regular meal. Unresolved IDs, duplicate names and absent allergen source are diagnosed as unknown rather than treated as allergen-free; no alias, word guess, date or live-population pin is introduced.

The independently authored `tests/checks/c2a_current_corn_loss.mjs` remains unchanged and now fails the new source-warning assertion. Additional read-only `swap-corn` and `replace-corn` variants follow whichever exact known-Corn current meal exists, moving or replacing its complete meal fields and rebuilding coherent outputs. These cases ensure the repair follows the binding rather than restoring the historical location requirement. The original verification below records the pre-review handoff; the repair receipt records the added assertions and current isolation limits.

## Verification

The original baseline ran 598 tests: 594 passed, four skipped, zero failed. The revised existing suite runs 596: 585 pass, eleven explicit optional-source skips, zero failures. The net count change is two removed release-scope tests (three removed, one additional lactose case); seven former false passes now report skips.

The full revised suite passed each read-only variation: unchanged baseline, inert app comment, whole W1 Sunday/Monday breakfast swap, W2 sausage-dinner replacement by another complete meal, removal of the lactose cohort, and removal of the anaphylactic cohort. Menu/roster variants rebuild routing with the real exporter/plating engine and refresh matching provenance. No production file is written by the probes.

Deliberate fault probes remain red:

- Remove Corn from Peas and Corn's baked source record: one Corn source assertion fails.
- Map Lactose Intolerant to Gluten instead of Dairy: four lactose assertions fail.
- Make `doorIsAnaphResident` always false: five flag/count/containment assertions fail.
- Clear a current brassica dish's published Brassicas flag: the current-data flag assertion fails.

Aggregate results, source/fixture hashes and test-file inventory are in `docs/receipts/door_c2a_verification_2026-11-06.json`. Local runtime was Node 24.19.0. Normal Node test subprocesses were denied by this sandbox (`spawn EPERM`), so verification used Node's in-process `--experimental-test-isolation=none`; CI remains Node 22 and must run its unchanged normal command before fold. These tests are not a hosted benchmark or a staff-device trial.

F1 was being built concurrently. To keep this slice's result reviewable, the probe reads a temporary `git show 8066a1f:index.html` snapshot through `C2A_SOURCE_HTML`; it excludes the new deliberately red F1a gate from this baseline-slice run. The final combined implementation must run both slices together. The gate author did not edit product code, workflows or F1a tests.

## Reproduction and ownership

Run ordinary tests with `node --test tests/*.mjs`. For a read-only variation, set `C2A_VARIANT` to one of the documented names and use `node --experimental-test-isolation=none --import ./tests/checks/c2a_variation.mjs --test <gate files>`. `C2A_SOURCE_HTML` is optional and only needed to pin a source revision during concurrent development. The probe is outside the default test glob and introduces no workflow or runner allocation.

The parent builder owns F1's adaptation of old smoke/outbox/revert harnesses and side-publish expectations. In particular, the Corn helper's pre-F1 save stub and exact side-publish assertion must migrate under F1's transaction coverage; do not delete their persistence/stamping assertions to make F1 green. C2a changes in `swap_revert_reaches_gate.mjs` are confined to the final historical-data assertion.
